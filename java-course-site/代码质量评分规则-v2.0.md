# 代码质量评分规则说明（v2.0）

> 适用范围：Java 学习中心「写代码 → 运行检测」环节的自动评分。
> 规则版本：**v2.0**　通过线：**60 分**（满分 100）　最近更新：2026-10-01
>
> **唯一事实来源**：本文档由 `index.html` 中的 `CODE_QUALITY_RUBRIC` 常量与 `scoreCodeQuality()` 函数逐条整理而成。
> 当两者不一致时，**以代码为准**；任何规则改动必须同时修改「常量 → 评分函数 → 评分卡细则表 → 本文档」四处（见文末第 9 节同步检查表）。

---

## 1. 总体设计：先"体检"，后"打分"

检测完全对标 Visual Studio Code + Java 扩展（JDT.LS）的工作方式，分两步：

```
学生代码
  │
  ▼
① checkCode + javaVscAnalyze（模拟 VS Code 三阶段检测）
     · compile 阶段：javac -encoding UTF-8 -d bin ……  编译错误
     · run     阶段：java -Dfile.encoding=UTF-8 -cp bin ……  启动错误（退出码 0/1）
     · check   阶段：教学校验（是否有输出、输出是否与预期逐字匹配）
   产出：errors[]（错误）/ warnings[]（警告）/ matchPct（输出匹配率 0–100）
  │
  ▼
② scoreCodeQuality（5 维规则化评分）
     · 每个维度从满分开始，按固定 RULE-ID 逐条扣分
     · 编译失败 → 三个维度封顶 + RULE-G01 全局硬闸口
     · 无论检测是否通过，都生成 0–100 分的完整报告
```

关键原则：

1. **通过/失败都出分**——编译失败的代码同样给出各维度得分与改进建议，只是分数被规则限制。
2. **纯静态、确定性分析**——没有随机项、没有时间因子，同一份代码任何时候检测，分数与评分指纹完全一致。
3. **每一分都可解释**——每条扣分携带规则 ID、扣分原因和修复建议，评分卡中可逐条追溯。

## 2. 评分维度与权重总览

| 维度 | ID | 权重 | 维度满分（默认权重下） | 考查内容 |
|---|---|---|---|---|
| 代码规范性 | `specification` | **25** | 25 | 命名、语法编译错误、大小写、缩进、分号、import |
| 逻辑完整性 | `logic` | **30** | 30 | class/main 入口、输出语句、输出与预期匹配度 |
| 错误处理能力 | `errorHandling` | **20** | 20 | 输入校验、除零、整数除法、异常处理、资源关闭、硬编码密钥 |
| 性能效率 | `performance` | **15** | 15 | 循环内创建对象、循环内字符串拼接、IO 输出次数 |
| 可读性 | `readability` | **10** | 10 | 变量命名、行宽、注释 |
| **合计** | — | **100** | 100 | — |

- 维度满分按权重归一化计算：`维度满分 = round(权重 ÷ 权重总和 × 100)`。默认权重合计 100，所以维度满分恰好等于权重。
- 分数解释（代码中唯一生效的分界是 60 分）：
  - **60–100 分：通过**，参考答案自动解锁。
  - **0–59 分：未通过**，按评分卡中的 RULE 建议修改后重新检测。
  - 其中 59 分是特殊值：代码本身得分可能已达 60，但因存在未修复错误，被 **RULE-G01 硬闸口**压到 59（见第 7 节）。

## 3. 评分计算流程（评分函数内部步骤）

1. 各维度以满分起步，初始化 `deductions`（扣分明细）、`caps`（封顶记录）。
2. 按第 4–8 节的规则顺序检测并扣分。扣分使用 clamp：`维度分 = max(0, 当前分 − 扣分值)`，任何维度不会出现负分。
3. 若存在编译错误（`errors.length > 0`，警告不算），依次执行三个维度封顶（见第 7 节），封顶只在当前分高于上限时生效。
4. 归一化汇总：

   ```
   总分 = round( Σ各维度实得分 ÷ Σ各维度满分 × 100 )
   ```

   默认权重下分母为 100，即各维度得分直接相加。
5. 执行 **RULE-G01 全局硬闸口**：存在错误且总分 ≥ 60 时，总分强制改为 59。
6. 生成评分指纹（第 8 节），返回完整报告。

> 注意：扣分规则的**分值是固定值**（如 -6、-2），按默认权重设计。若自定义了权重（第 10 节），维度满分会随权重变化，但单次扣分值不变。

## 4. 维度一：代码规范性（25 分）

| 规则 ID | 分值 | 触发条件（与代码判定一致） | 扣分/封顶 |
|---|---|---|---|
| `RULE-S01` | -4 | 存在 `class 名称` 且类名首字母不是大写（不符合 PascalCase） | 命中一次扣 4 |
| `RULE-S02` | -5/条 | 错误信息中含「中文 / 括号 / 闭合 / 引号 / 多余的」任一字样的**语法类编译错误**（中文弯引号、括号不匹配/不闭合/多余、字符串或字符引号未闭合） | 每条 -5，本规则**最多 -15** |
| `RULE-S03` | -4/条 | 错误信息中含「大写 / 不是 system / 不是 SYSTEM」的**符号大小写错误**（对应 `System.out.println` 的五种拼写错误） | 每条 -4，本规则**最多 -12** |
| `RULE-S04` | -2 | 同一份代码中 Tab 缩进与 4 空格缩进混用 | 命中扣 2 |
| `RULE-S05` | -1/条 | 警告中出现「分号」提示（输出语句、变量声明/赋值行缺 `;`） | 每处 -1，**最多 -4** |
| `RULE-S06` | -2/条 | 警告中出现「导入 / import」提示（使用了 JDK 类型但缺少 import） | 每处 -2，**最多 -4** |

说明：

- S02 与 S03 使用**互不相交的错误过滤器**分类，同一条错误只计入一个规则，不会重复扣分。
- 未使用的 import 属于警告（见 W-IMPORT），会计入 S06。

反例 → 正例：

```java
// ❌ S01：类名首字母小写
class hello { … }
// ✅
class Hello { … }

// ❌ S03：System 首字母小写
system.out.println("Hi");
// ✅
System.out.println("Hi");

// ❌ S04：本行用 Tab、下一行用空格混用
// ✅ 统一使用 4 个空格（VS Code 右下角可切换）
```

## 5. 维度二：逻辑完整性（30 分）

| 规则 ID | 分值 | 触发条件 | 扣分方式 |
|---|---|---|---|
| `RULE-L01` | -10（缺 public 时 -3） | 不存在完整入口 `public static void main(String[] args)`（也接受 `String args[]` 写法）。**例外**：方法存在但仅缺少 `public` 修饰符，只扣 3 分 | 按情形扣 10 或 3 |
| `RULE-L02` | -4 | 代码中找不到任何 `class 名称` 声明 | 命中扣 4 |
| `RULE-L03` | -6 | 代码中不含 `System.out.print` / `System.out.println` | 命中扣 6 |
| `RULE-L04` | 最高 -18 | 输出与练习预期的逐字匹配率 `matchPct` 低于 100：`扣分 = round(18 × (1 − matchPct/100))`；**完全没有输出语句时直接扣 18**（按匹配率 0% 计） | 按匹配率线性扣分 |
| `CAP-LOGIC` | 封顶 | 编译失败时，本维度得分**封顶为满分的 50%**（默认即 ≤15 分）——程序无法运行，逻辑不可验证 | 封顶规则 |

- 匹配率由 `checkCode` 对照练习预期输出逐字符计算（大小写、标点、空格、换行均敏感）。
- L03 与 L04 联动：没有输出语句时两条规则都会命中（-6 与 -18）。
- `Main`（首字母大写）、参数列表错误等入口问题，javac 可以编译通过，但 java 启动阶段会失败，对应诊断 `ENTRY-01`（见第 6 节），同样在 L01 中扣分。

## 6. 维度三：错误处理能力（20 分）

本维度规则**只在代码使用了相关特性时才触发**，不使用不扣分（初学者尚未学到的内容不惩罚）。

| 规则 ID | 分值 | 触发条件 | 修复方向 |
|---|---|---|---|
| `RULE-E01` | -6 | 调用了 `nextInt()/nextDouble()/nextLong()/nextFloat()`，但全代码没有任何 `hasNext…` 类型校验 | 先 `if(sc.hasNextInt())` 再 `nextInt()`，防止 `InputMismatchException` |
| `RULE-E02` | -6 | 检测到「变量 / 变量」形式的除法，且代码中没有 `!=0`、`==0`、`>0`、`>=0` 等零值判断 | 除法前确认除数不为 0：`if(b != 0){ int c = a / b; }` |
| `RULE-E03` | -4 | 出现「整数 / 整数」字面量除法，且代码未出现 `double`/`float` | `5/2` 结果是 `2`；要得到 `2.5` 写 `5.0/2` 或 `(double)` 强转 |
| `RULE-E04` | -4 | `new` 了 `Scanner/File/FileReader/BufferedReader/FileWriter/InputStreamReader` 等外部资源，但没有 `try {` 也没有 `throws` | 用 try-catch 包裹，或在 main 上声明 `throws Exception` |
| `RULE-E05` | -2 | 使用了 `new Scanner(...)` 但没有调用 `.close()` | 用完执行 `sc.close();` 释放资源 |
| `RULE-E06` | -3 | 出现 `password/passwd/pwd/secret/token = "…"` 形式的硬编码敏感信息（大小写不敏感） | 敏感信息应从配置或环境变量读取，不写死在源码中 |
| `CAP-EH` | 封顶 | 编译失败时本维度**封顶为满分的 70%**（默认 ≤14 分） | 封顶规则 |

## 7. 维度四：性能效率（15 分）

| 规则 ID | 分值 | 触发条件 | 修复方向 |
|---|---|---|---|
| `RULE-P01` | -6 | `for(…){ … new Xxx() … }` 或 `while(…){ … new Xxx() … }`：循环体内创建对象 | 对象创建提到循环外，循环内复用 |
| `RULE-P02` | -4 | for 循环体内使用 `+` 做字符串拼接 | 循环外建 `StringBuilder`，循环内 `append` |
| `RULE-P03` | -2 | `System.out.print/println(` 调用次数 **> 5** | 先拼接再一次性输出，减少 IO 次数 |
| `CAP-PERF` | 封顶 | 编译失败时本维度**封顶为满分的 60%**（默认 ≤9 分） | 封顶规则 |

## 8. 维度五：可读性（10 分）

| 规则 ID | 分值 | 触发条件 | 扣分/封顶 |
|---|---|---|---|
| `RULE-R01` | -2/个 | 声明了单字母变量且名字不在豁免名单 `i / j / k / n` 内（循环计数器豁免） | 每个 -2，**最多 -4** |
| `RULE-R02` | -1/行 | 去除首尾空白后单行长度 **> 100 字符** | 每行 -1，**最多 -3** |
| `RULE-R03` | -2 | 有效代码行 **> 10 行**，但全代码没有任何 `//` 或 `/*` 注释 | 命中扣 2 |

"有效代码行"指非空、且不是纯注释（`//`、`/*`、`*` 开头）的行。

```java
// ❌ R01：a 语义不明（循环变量 i 除外）
int a = 20;
// ✅
int age = 20;
```

## 9. VS Code 诊断规则 ID 对照表（Problems 面板）

`javaVscAnalyze` 产出的每条诊断都带固定 ID，显示在模拟 VS Code 窗口的终端与 Problems 面板中。**它们是评分规则的输入来源**：error 进入 `errors[]`，warning 进入 `warnings[]`。

### 9.1 compile 阶段（javac 编译）

| 诊断 ID | 严重程度 | 含义 | 主要影响的评分规则 |
|---|---|---|---|
| `COMP-ENC-01` | error | 非法字符：中文弯引号 “ ”（U+201C/U+201D），只报首个位置 | S02，并触发编译失败 |
| `SYN-BRK-01` | error | 括号多余、类型不匹配或未闭合（`{}` `()` `[]`） | S02，并触发编译失败 |
| `SYN-STR-01` | error | 双引号字符串未闭合 | S02，并触发编译失败 |
| `SYN-CHAR-01` | error | 单引号字符未闭合 | S02，并触发编译失败 |
| `SYM-01` | error | `System.Out.print`：`out` 必须全小写 | S03，并触发编译失败 |
| `SYM-02` | error | `Println` 必须全小写 | S03，并触发编译失败 |
| `SYM-03` | error | `system.out…`：`System` 首字母必须大写 | S03，并触发编译失败 |
| `SYM-04` | error | `SYSTEM`：`System` 只首字母大写 | S03，并触发编译失败 |
| `SYM-05` | error | `Print` 必须全小写 | S03，并触发编译失败 |
| `W-CLASS` | warning | 找不到 class 声明 | （L02 另行直接判定） |
| `W-SEMI` | warning | 输出语句或变量声明/赋值行可能缺少分号 | S05 |
| `W-IMPORT` | warning | 类型缺少 import（"X cannot be resolved to a type"）或 import 从未使用（"The import … is never used"） | S06 |

### 9.2 run 阶段（java 启动器）

| 诊断 ID | 严重程度 | 含义 | 影响 |
|---|---|---|---|
| `ENTRY-01` | error | 三种情形：写成 `Main`（大写）/ main 参数列表不是 `String[] args` / 根本没有 main 方法 | L01；属运行期错误，参与 RULE-G01 判定 |
| `W-PUBLIC` | warning | main 方法缺少 `public` 修饰符 | L01 仅扣 3 分的情形 |

### 9.3 check 阶段（教学校验）

| 诊断 ID | 严重程度 | 含义 | 影响 |
|---|---|---|---|
| `CHK-PRINT-01` | error | 没有 `System.out.print/println` 输出语句 | L03、L04；参与 RULE-G01 判定 |
| `CHK-OUT-01` | **匹配率 < 50% 时为 error，否则为 warning** | 输出内容与预期不符 | L04 线性扣分；匹配率 <50% 时同时触发编译失败标记与 RULE-G01 |

## 10. 编译失败封顶与 RULE-G01 全局硬闸口

判定"编译失败"的唯一条件：**`errors.length > 0`**（即上表中的 error 诊断至少一条；纯 warning 不算失败）。

失败后两道机制依次生效：

1. **维度封顶**（在所有扣分完成后执行，只压低不抬高）：
   - 逻辑完整性 ≤ 满分 50%（`CAP-LOGIC`）
   - 错误处理能力 ≤ 满分 70%（`CAP-EH`）
   - 性能效率 ≤ 满分 60%（`CAP-PERF`）
2. **RULE-G01 全局硬闸口**：若归一化总分 ≥ 60，强制改为 **59**，评分卡顶部显示红色闸口条。

设计意图：

- 代码规范性、可读性属于"看代码就能评价"的维度，失败也照常给分；
- 逻辑/错误处理/性能依赖程序实际可运行，失败时只能按"可验证部分"给分；
- 60 分是参考答案解锁线，**退出码非 0 的代码不允许越过解锁线**，但学生仍能看到距离满分差在哪里。

## 11. 可复现性与评分指纹

每次评分返回的 `meta` 字段：

| 字段 | 说明 |
|---|---|
| `formula` | 归一化计算公式文案，分母为各维度满分之和 |
| `basis` | 指纹基串，格式：`v=<版本>;len=<代码字符数>;hits=<规则ID>x<命中次数>,…`（规则 ID 按字典序排列） |
| `fingerprint` | 指纹：`<版本>-<djb2哈希的十六进制大写>`。djb2 种子 5381，逐字符迭代 `hash = ((hash<<5)+hash+charCode) >>> 0` |

命中计数同时包含扣分规则（deductions）与封顶规则（caps）；触发硬闸口时额外计入 `RULE-G01x1`。

因此：**代码相同 → 命中规则相同 → 基串相同 → 指纹与分数相同**，便于学生自查"我改了哪里、分数为什么变了"，也便于教师复核。

## 12. 权重自定义接口

```js
setRubricWeights({ specification:25, logic:30, errorHandling:20, performance:15, readability:10 });
```

- 五个维度 ID 必须全部提供且为 ≥0 的数字，任一非法则整体不生效并返回 `false`。
- 设置后写入 `localStorage` 键 `java-rubric-v2`（含版本号、通过线、各维度权重），下次打开页面自动加载；旧键 `java-rubric-v1` 仅在 v2 不存在时迁移同名维度。
- 通过线 `passingScore` 同样可随存档恢复，默认 60。
- 自定义权重后维度满分按新权重归一化，规则固定扣分值不变（见第 3 节注意事项）。

|---|---|---|---|---|---|---|---|---|
| A. 标准 HelloWorld | 通过 | 25 | 30 | 20 | 15 | 10 | **100** | 无任何命中 |

| D. 中文弯引号 | 1 error | 20（S02） | 15（封顶） | 14（封顶） | 9（封顶） | 10 | **59** | COMP-ENC-01 定位到首个弯引号 |

| H. 括号不闭合 + `Main` 大写 | 2 errors | 16（S02） | 15（L01，封顶） | 14（封顶） | 9（封顶） | 10 | **59** | SYN-BRK-01 + ENTRY-01 |

## 14. 规则变更同步检查表（开发者必读）

修改任何评分规则时，必须四处同步，缺一不可：

1. [ ] `CODE_QUALITY_RUBRIC` 常量中的规则 ID、分值、描述；
2. [ ] `scoreCodeQuality()` 中对应的判定与扣分/封顶逻辑；
3. [ ] 评分卡折叠区（`renderQualityCard` 自动读取常量渲染细则表，一般无需手改，但需检查展示是否正确）；
4. [ ] 本文档对应章节及第 13 节回归基准；改完跑回归用例确认 A=100、B/D/G/H=59(gateCapped)、E=86、指纹确定性不变。

边界约定（改动时勿破坏）：

- 错误分类过滤器必须保持**互不相交**，避免一条错误在 S02/S03 重复计数；
- `compileFailed` 只认 `errors.length > 0`，警告永远不触发封顶与 G01；
- 中文弯引号检测使用码点判定（`U+201C / U+201D`），不要在正则字面量中直接写弯引号字符；
