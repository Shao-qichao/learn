## 2. 技术栈与设计要点

- **Electron 33**：桌面壳，课程内容仍是纯静态 HTML，无构建步骤
- **electron-builder 25**：Windows（NSIS）、macOS（DMG）、Linux（AppImage/deb）打包
- **零运行时依赖**：`dependencies` 为空，仅开发期需要 electron 与 electron-builder

### 2.1 路径适配（桌面版的核心）

`index.html` 中存在三类写死的开发机绝对路径，桌面版在启动时做**运行时替换**（见 `desktop/main.js` 的 `buildRuntimeHtml()`）：

| 文件中的原始形式 | 出现位置 | 替换为 |
|------------------|---------|--------|
| `D:\\java学习中心\\javacourse`（JSON 转义） | practiceData 的 `path` 字段（48 处） | 本机「文档/Java学习中心/javacourse」（JSON 转义） |
| `vscode://file/c%3A/Users/13053/JavaLearning` | 章项目静态卡片（27 处） | 本机章项目目录的 vscode URL |
| `c:/Users/13053/JavaLearning` | 课文示例文本（2 处） | 本机章项目目录（正斜杠形式） |

生成的运行时副本写到 `userData/runtime/index.html` 后再 `loadFile`，**不修改包内原始文件**。

### 2.2 用户工作区

- 位置：`app.getPath('documents')/Java学习中心/`
  - `javacourse/`：练习模板副本。启动时 `syncPractice()` 只复制**不存在**的子目录，学生已改的代码不覆盖
  - `JavaLearning/`：章项目代码目录
- 目录跟随系统「文档」重定向（如被移到 D 盘）

### 2.3 外部协议处理

`vscode://`、`http(s)://` 等非 file 链接统一通过 `shell.openExternal()` 交给系统，禁止应用内导航（`will-navigate` + `setWindowOpenHandler`）。

## 3. 本地开发

### 3.1 环境要求

- Node.js 18+（仓库在 Node 24 / npm 11 上验证）
- 网络受限环境建议使用镜像：

```powershell
$env:ELECTRON_MIRROR="https://npmmirror.com/mirrors/electron/"
$env:ELECTRON_BUILDER_BINARIES_MIRROR="https://npmmirror.com/mirrors/electron-builder-binaries/"
```

### 3.2 常用命令

```powershell
cd desktop
npm install              # 安装依赖
npm start                # 开发模式启动应用
npm run selfcheck        # 自检：生成运行时页面并断言旧路径零残留
npm run dist:win         # 仅打 Windows 安装包
npm run dist:mac         # 仅打 macOS DMG（x64 + arm64）
npm run dist:linux       # 仅打 Linux AppImage + deb
npm run dist:all         # 三平台全包（仅建议在 CI 上跑）
```

> npm 11 默认拦截依赖的 install 脚本，若 electron 二进制未下载，手动执行：
> `node node_modules/electron/install.js`

### 3.3 自检机制

`npm run selfcheck` 以 `--selfcheck` 启动主进程：
1. 同步练习模板到工作区
2. 生成运行时 index.html
3. 断言三类旧硬编码路径**零残留**
4. 打印结果并退出（CI 中退出码非 0 即失败）

### 3.4 修改课程内容后

- 改 `java-course-site/index.html`：直接生效（开发态与打包都从该目录取）
- 新增练习：在 `javacourse/` 加模板目录，并在 index.html 的 practiceData JSON 中补条目；注意新增路径若不再使用三类硬编码前缀，需要同步更新 `main.js` 的替换规则与自检断言

## 4. 打包配置说明（desktop/package.json 的 build 字段）

| 配置 | 值 | 说明 |
|------|----|------|
| `extraResources` | `../java-course-site → resources/site`、`../javacourse → resources/practice` | 课程与练习随安装包分发，不打进 asar |
| `site` 过滤 | `!tools/**` | 环境安装脚本不进桌面包 |
| NSIS | 非一键、按用户安装、可选目录、桌面+开始菜单快捷方式 | 产物 `Java学习中心-Setup-<ver>.exe` |
| DMG | x64 + arm64 双架构 | 产物按架构命名 |
| Linux | AppImage + deb | 免安装通用包 + Debian 系安装包 |
| 图标 | `build/icon.ico`（256²）、`build/icon.png`（512²） | macOS icns 由 builder 从 png 自动生成 |

## 5. 发布流程（GitHub Actions）

工作流：`.github/workflows/release.yml`

### 5.1 触发方式

- **推 tag**：推送 `v*` 标签时自动触发
- **手动**：Actions 页面 → 「构建并发布桌面版」→ Run workflow，输入版本号

### 5.2 流水线做什么

```
matrix 构建（windows / macos / ubuntu 并行）
  ├─ actions/checkout
  ├─ setup-node 20
  ├─ npm ci
  ├─ npm run selfcheck         ← 路径替换自检（失败则中止）
  ├─ electron-builder 对应平台打包
  └─ upload-artifact 安装包
        ↓
release（ubuntu，needs: build，contents: write）
  ├─ 汇总三平台产物
  └─ softprops/action-gh-release 创建 Release（自动生成更新日志）
```

### 5.3 发布一个新版本

```powershell
# 1. 更新 desktop/package.json 中的 version
# 2. 提交所有改动
git add .
git commit -m "release: v1.0.1"
git push origin main

# 3. 打 tag 并推送（自动触发构建+发布）
git tag v1.0.1
git push origin v1.0.1
```

约 10-15 分钟后，在 <https://github.com/Shao-qichao/learn/releases> 可见：
- `Java学习中心-Setup-1.0.1.exe`
- `Java学习中心-1.0.1-arm64.dmg` / `x64.dmg`
- `Java学习中心-1.0.1-x86_64.AppImage` / `.deb`

版本号带 `-`（如 `v1.1.0-beta.1`）会自动标记为 **prerelease**。

### 5.4 注意事项

- macOS 产物未做 Apple 公证（notarization），用户首次打开需在「隐私与安全性」放行；如需消除提示，需加入 Apple Developer 账号的签名与公证步骤
- Windows 产物未做代码签名，SmartScreen 会在首次运行时提示，用户选择「仍要运行」
- tag 名必须以 `v` 开头，否则不会触发发布流水线

## 6. 故障排查

| 现象 | 排查 |
|------|------|
| `npm install` 后 electron 不存在 | 手动 `node node_modules/electron/install.js`（npm 11 拦截了 postinstall） |
| 打包下载 nsis/winCodeSign 卡住 | 设置 `ELECTRON_BUILDER_BINARIES_MIRROR` 为 npmmirror |
| 自检报「残留路径」 | index.html 出现了新写法的绝对路径，更新 main.js 的 split 规则和 selfcheck 断言 |
| 应用内练习按钮路径错误 | 查看 `userData/runtime/index.html`（菜单帮助里也可定位 userData），检查替换结果 |
| CI mac 构建图标失败 | 确认 `desktop/build/icon.png` 不小于 512×512 |
